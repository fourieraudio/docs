# Fourier Audio transform.core v1.7.0 Release Notes

- **transform**.core **Version**: 1.7.0  
- **Windows transform**.client **Version**: 1.7.0  
- **macOS transform**.client **Version**: 1.7.0

## Summary

**transform**.core v1.7 has landed\! Featuring:

* **⚡ HYPERPORT**: a new, lightning fast audio protocol, delivering a  1.2 ms roundtrip to DiGiCo consoles.  
* **🔌 Patch Bay**: easily see and modify the patches for your entire system in one view.

… and many other exciting improvements to the **transform** software\!

## New In This Release

- **TF-3658**: HYPERPORT provides an ultra low latency audio link between a **transform**.engine and a DiGiCo console. Controls to select an audio transport (Dante or HYPERPORT) have been added to the Settings tab.  
- **TF-870**: Added a patch bay in the Settings tab, to allow you to quickly adjust the patch between chains and input/output channels.  
- **TF-1114, TF-4567**: You can now steal patches from other chains, unpatch individual channels, and unpatch a chain entirely. This makes it easier to rearrange the patching of your show.  
- **TF-3246**: You can now edit plugin settings directly from a plugin grid by selecting the plugin title bar in the grid.  
- **TF-3645**: A handy bypass button in the plugin title bar of a grid view plugin lets you quickly bypass plugins.  
- **TF-32**: You can now see and modify the engine’s IP configuration (such as IP address and subnet prefix) in the **transform**.desktop client application.  
- **TF-4480**: A readout of the associated subnet mask (e.g. `255.255.255.0`) for a configured subnet prefix (e.g. `/24`) is shown in the networking tab.  
- **TF-4662**: A close button has been added to the detail pane of chains, allowing you to create more space in the UI if needed.  
- **NS-63:** You can now register the connected **transform**.engine via the desktop client, and the details of the registered owner are displayed when online.  
- **TF-4673**: macOS users can now copy and paste throughout the application.  
- **TF-28**: A button to reboot the connected engine is available in the System menu of the **transform**.desktop client application.

## Changed Functionality In This Release

- TF-2932: The “Delete” entry in the Action Menu now includes the type of the selected item, to make deletion more intuitive.  
- TF-4370: The OLED on the front of **transform**.engine will now display a warning triangle instead of “err\!” when an erroneous condition is detected, for better international recognition and consistency with **transform**.go.  
- TF-4941: Plugin view now remembers which plugin was previously selected when scrolling between chains.  
- TF-1793: The plugin host can now start even if the primary interface is not connected.  
- TF-4822: You can no longer configure a device to have a static IP address of `0.0.0.0`.  
- TF-4792: Under certain circumstances, **transform**.engine could enter an undesirable Energy Efficient Ethernet (EEE) mode. This is no longer possible.  
- TF-4646: Improved logging if a service fails.  
- TF-4824: Include logs from “test run” in downloaded logs from the engine.  
- TF-4892: Include additional information about low-level system performance in downloaded logs from engine.  
- TF-4973: Refined the threshold at which the status bar puck is shown for temperature-related warnings.  
- TF-4804, TF-4898: Clarify instructions for cleaning the unit if it is overheating.  
- TF-4918: Clear front panel warning indicator when system mode changes mean the unit is no longer in an error state.  
- TF-4715: The subnet prefix field now limits the input length during value entry.  
- TF-4188: Improve clarity of some network configuration validation errors.  
- TF-4168: Consistently refer to “unit” rather than “engine” in the desktop client.  
- TF-5173: Certain SSL certificates issued by eMudhra are no longer trusted when performing HTTPS operations originating from **transform**.client.

**NB** that from this release, we now refer to the software that runs on the **transform**.engine and **transform**.go hardware as **transform**.core.

## Bugs Fixed In This Release

- TF-4623: Under certain circumstances, after switching to Offline mode, the plugin host could still be running whereas the system believed it to be stopped, resulting in actions which require the plugin host to be offline (such as system upgrades) failing.  
- TF-5101: If a second desktop client modified the state of a plugin grid being displayed by a client, then those changes would not be shown until the grid was reloaded.  
- TF-4704: A rare plugin behaviour could cause an escape of the per-core isolation sandbox, resulting in interference on other DSP cores. Prevent sandbox escapes via this route.  
- TF-4735: In certain cases, repatching multiple chains very quickly could cause DSP meter spikes.  
- TF-4963: Under certain circumstances, after loading a showfile, the renderer could take a long time to reconfigure, or get stuck reconfiguring.  
- TF-3629, TF-4392: Very rarely, misbehaving USB devices during connect / disconnect could cause the plugin host to go offline.  
- TF-4920, TF-4921: In certain very rare cases, Maestro could fail to start with an error relating to licensing.  
- TF-4981: In very rare circumstances, no USB devices would be recognised in the rear USB bay.  
- TF-4592: Keyboard navigation is once again possible through the list of plugins in the library tab.  
- TF-4687: On the connection screen, when the client computer IP is changed from an outside a device’s subnet to an address within the device’s subnet, metadata about the discovered device is not shown.  
- TF-4688: On the connection screen, if a previously-connected device was discovered on the network with an IP address which was not currently connectable, the “discovered device not connectable” display was not shown.  
- TF-4696: On the connection screen, discovered engines could be briefly displayed as being unconnectable on startup.  
- TF-4778: On the connection screen, clicking a device could cause the list of devices to re-order under your cursor.   
- TF-4796: On the connection screen, if a device ceased to be available, it would remain listed as “Discovered”.  
- TF-4807: On the connection screen, under certain rare circumstances, two instances of a device could be shown.  
- TF-4808: On the connection screen, previously-connected but currently unconnectable devices could cause discovered devices to flicker.  
- TF-4861: In certain pathological cases, log files could fail to download after growing very large. Download now succeeds in this case.  
- TF-4827: A potential security flaw, RUSTSEC-2026-0111 was discovered with one of the third party components utilised by **transform**.core. The issue has been patched, and there was no known impact to **transform**.core software.

## Compatibility Notes

Showfiles are fully backwards and forwards-compatible with **transform**.engine v1.1 \- v1.7.

**transform**.engine v1.7 is fully backwards compatible with **transform**.client v1.0-v1.7, and vice-versa; you can connect to an engine running v1.6 from a client running v1.7, and to an engine running v1.7 from a client running v1.6.

Downgrading to versions prior to v1.7 is not possible once v1.7 has been installed.

## Known Issues

Users should be aware of the following known issues in this release, which we hope to address in a future update:

- **TF-2698**: When bx\_limiter and AMEK EQ 200 are used in a chain, recalling cues can cause a momentary increase in DSP load. We are working with the plugin publisher to resolve this issue.  
- **TF-3434**: It is possible for multiple network interfaces to be configured with overlapping subnets via DHCP, causing IP network issues.

A small number of plugins may experience compatibility issues running on **transform**.engine. For details, see our plugin compatibility database at [https\://plugins.fourieraudio.com](https://plugins.fourieraudio.com) .
